# MVP1: 로그인 및 JWT 토큰 발급

```mermaid
sequenceDiagram
    autonumber
    actor Client as User
    participant Auth as AuthController
    participant Sec as Security/JwtProvider
    participant DB as Database

    Client->>Auth: email, password 입력
    Auth->>DB: email로 회원(User) 조회
    alt 회원이 없거나 비밀번호 불일치
        DB-->>Auth: 조회 실패 / 비밀번호 불일치
        Auth-->>Client: message: "아이디 또는 비밀번호 불일치"
    else 인증 성공
        DB-->>Auth: 회원 정보 반환
        Auth->>Sec: JWT 생성 요청
        Sec-->>Auth: 토큰 생성 완료
        Auth-->>Client: 200 OK
    end
```

# **MVP1: 멘토 신청 및 관리자 승인/거절**

```mermaid
sequenceDiagram
    actor User
    participant UserController
    participant MentorService
    participant NotificationService
    participant Database
    actor Admin
    participant AdminController

    User->>UserController: 멘토 신청 요청
    UserController->>MentorService: applyForMentor(userId)
    MentorService->>Database: 이미 대기중인 신청 있는지 확인
    alt 이미 대기중인 신청 존재
        MentorService-->>User: 409 재신청 불가
    else 신청 가능
        MentorService->>Database: MentorApplication(PENDING) 저장
        MentorService->>NotificationService: 관리자에게 신청 알림 발송
        MentorService-->>User: 200 신청 완료
    end

    Admin->>AdminController: 신청 대기 목록 조회
    AdminController-->>Admin: 대기 목록 반환

    alt 승인
        Admin->>AdminController: 승인 처리
        AdminController->>MentorService: approveMentor(userId)
        MentorService->>Database: User.role → MENTOR 변경, 신청 상태 APPROVED
        MentorService->>NotificationService: 신청자에게 승인 알림 발송
        MentorService-->>Admin: 200 승인 완료
    else 거절
        Admin->>AdminController: 거절 처리
        AdminController->>MentorService: rejectMentor(userId)
        MentorService->>Database: 신청 상태 REJECTED (role 변경 없음)
        MentorService->>NotificationService: 신청자에게 거절 알림 발송
        MentorService-->>Admin: 200 거절 완료
    end
```

# **MVP2: 결제수단(빌링키) 등록**

```mermaid
sequenceDiagram
    actor User
    participant PaymentMethodController
    participant PaymentMethodService
    participant PG as PortOne
    participant Database

    User->>PaymentMethodController: 카드 등록 요청
    PaymentMethodController->>PaymentMethodService: prepareBillingKeyIssuance(userId)
    PaymentMethodService->>Database: issueId 발급 준비 저장
    PaymentMethodService-->>User: issueId 반환
    User->>PG: (프론트) requestIssueBillingKey(issueId, 카드정보)
    PG-->>User: billingKey 발급 완료
    User->>PaymentMethodController: 결제수단 등록 요청(cardNickname, issueId, billingKey, phoneNumber)
    PaymentMethodController->>PaymentMethodService: registerPaymentMethod()
    PaymentMethodService->>PG: billingKey 재조회 검증
    PG-->>PaymentMethodService: 검증 결과
    alt 검증 실패
        PaymentMethodService-->>User: 400 등록 실패
    else 검증 성공
        PaymentMethodService->>Database: PaymentMethod 저장
        PaymentMethodService-->>User: 201 등록 완료
    end
```

# **MVP2: 구독 신청 및 최초 결제**

```mermaid
sequenceDiagram
    actor User
    participant SubscriptionController
    participant PaymentPrepareService
    participant PG as PortOne
    participant Database

    User->>SubscriptionController: 구독 신청(mentorId, planId)
    SubscriptionController->>PaymentPrepareService: subscribe(userId, mentorId, planId)
    PaymentPrepareService->>Database: 등록된 결제수단(billingKey) 조회
    PaymentPrepareService->>PG: billingKey로 즉시 결제 요청(S2S)
    PG-->>PaymentPrepareService: 결제 승인 결과
    alt 결제 성공
        PaymentPrepareService->>Database: Payment 상태 PAID, Subscription ACTIVE 전환
        PaymentPrepareService->>Database: Settlement 레코드 생성(PG수수료 3%, 플랫폼수수료 10% 차감)
        PaymentPrepareService->>PG: 다음 회차 결제 예약(createSchedule)
        PaymentPrepareService-->>User: 201 구독 완료
    else 결제 실패
        PaymentPrepareService->>Database: Payment 상태 FAILED
        PaymentPrepareService-->>User: 400 결제 실패
    end
```

# **MVP2: 정기 결제 자동 갱신**

```mermaid
sequenceDiagram
    participant PG as PortOne
    participant WebhookController
    participant PortOneWebhookVerifier
    participant PaymentSyncService
    participant Database

    Note over PG: 이전 결제 성공 시 예약해둔 일정(createSchedule)에 따라<br/>결제일 도래 시 PortOne이 자동으로 카드 청구
    PG->>WebhookController: 결제 결과 웹훅 전송(webhook-signature 포함)
    WebhookController->>PortOneWebhookVerifier: 서명 검증
    alt 서명 불일치
        PortOneWebhookVerifier-->>WebhookController: 검증 실패
        WebhookController-->>PG: 4xx
    else 검증 성공
        WebhookController->>PaymentSyncService: syncFromWebhook(paymentId)
        PaymentSyncService->>PG: 결제 정보 재조회(금액·상태 대조)
        alt 결제 확정
            PaymentSyncService->>Database: Subscription 다음 결제일 갱신, Settlement 생성
            PaymentSyncService->>Database: 결제 성공 알림 생성
        else 결제 실패
            PaymentSyncService->>Database: Payment FAILED, 결제 실패 알림 생성
        end
        WebhookController-->>PG: 200 OK
    end

    Note over Database: 별도 SubscriptionScheduler(매시간 주기)는<br/>이 결제 흐름과 무관하게, 이미 만료일이 지난<br/>구독을 EXPIRED로 정리하는 역할만 수행
```

# **MVP2: 채팅방 생성 및 재활성화**

```mermaid
sequenceDiagram
    actor User
    participant ChatController
    participant ChatService
    participant SubscriptionService
    participant Database

    User->>ChatController: 상담 신청(mentorId)
    ChatController->>ChatService: getOrCreateRoom(userId, mentorId)
    ChatService->>ChatService: 본인(멘토)에게 신청한 건지 확인
    alt 본인에게 신청
        ChatService-->>User: 400 잘못된 요청
    else 정상 요청
        ChatService->>SubscriptionService: checkAccessPermission(userId, mentorId)
        alt 구독 권한 없음
            SubscriptionService-->>ChatService: 접근 거부
            ChatService-->>User: 403 접근 거부
        else 구독 권한 있음
            ChatService->>Database: 기존 채팅방(mentorId, subscriberId) 조회
            alt 기존 방 없음
                ChatService->>Database: 새 채팅방 생성
            else 기존 방 있음
                Database-->>ChatService: 기존 방 반환(메시지 이력 유지)
            end
            alt 종료된 방(ended_by 있음)
                ChatService->>Database: 재활성화(양쪽에 다시 노출)
            end
            ChatService-->>User: 200 채팅방 반환
        end
    end
```

# **MVP2: 구독자 전용 게시글(멘토 게시판) 조회 — 페이월 체크**

```mermaid
sequenceDiagram
    actor User
    participant MentorPostController
    participant MentorPostService
    participant SubscriptionService
    participant Database

    User->>MentorPostController: 게시글 상세 조회(mentorId, postId)
    MentorPostController->>MentorPostService: getPost(userId, mentorId, postId)
    MentorPostService->>Database: 게시글 조회
    alt 공개 게시글
        MentorPostService-->>User: 200 게시글 반환
    else 비공개(구독자 전용) 게시글
        MentorPostService->>SubscriptionService: checkAccessPermission(userId, mentorId)
        SubscriptionService->>Database: 구독 상태 조회
        alt 본인(멘토) 또는 구독 중
            SubscriptionService-->>MentorPostService: 접근 허용
            MentorPostService-->>User: 200 게시글 반환
        else 미구독
            SubscriptionService-->>MentorPostService: 접근 거부
            MentorPostService-->>User: 403 접근 거부
        end
    end
```

# **MVP2: 환불 요청 및 관리자 승인 처리**

```mermaid
sequenceDiagram
    actor User
    participant PaymentController
    participant PaymentCancellationService
    actor Admin
    participant AdminController
    participant PG as PortOne
    participant Database

    User->>PaymentController: 환불 요청(paymentId, reason)
    PaymentController->>PaymentCancellationService: requestCancellation()
    PaymentCancellationService->>Database: PaymentCancellation(PENDING) 저장
    PaymentCancellationService-->>User: 201 요청 접수

    Admin->>AdminController: 환불 요청 목록 조회
    AdminController-->>Admin: 대기 목록 반환

    Admin->>AdminController: 환불 승인
    AdminController->>PaymentCancellationService: approve(cancellationId)
    PaymentCancellationService->>PG: 결제 취소 요청
    alt 취소 성공
        PG-->>PaymentCancellationService: 취소 완료
        PaymentCancellationService->>Database: Payment CANCELED, Settlement CANCELED
        PaymentCancellationService-->>Admin: 200 처리 완료
    else 취소 실패
        PG-->>PaymentCancellationService: 취소 실패
        PaymentCancellationService->>Database: 실패 사유 기록(REQUIRES_NEW 트랜잭션)
        PaymentCancellationService-->>Admin: 500 처리 실패
    end
```

# **MVP2: 멘토 정산 출금 신청 및 관리자 완료 처리**

```mermaid
sequenceDiagram
    actor Mentor
    participant SettlementController
    participant SettlementService
    actor Admin
    participant AdminController
    participant Database

    Mentor->>SettlementController: 출금 신청
    SettlementController->>SettlementService: requestWithdrawal(mentorId)
    SettlementService->>Database: PENDING 상태 정산 건 조회
    alt 대기중인 정산금 없음
        SettlementService-->>Mentor: 400 출금 가능 금액 없음
    else 대기중인 정산금 있음
        SettlementService->>Database: 상태 REQUESTED로 일괄 변경
        SettlementService-->>Mentor: 200 신청 완료
    end

    Admin->>AdminController: 전체 정산 목록 조회
    AdminController-->>Admin: 목록 + 정산 계좌 정보 반환

    Admin->>AdminController: 송금 완료 처리
    AdminController->>SettlementService: completeSettlement(settlementId)
    alt 상태가 REQUESTED가 아님
        SettlementService-->>Admin: 409 처리 불가
    else 상태가 REQUESTED
        SettlementService->>Database: 상태 COMPLETED로 변경
        SettlementService-->>Admin: 200 완료
    end
```
